## Оптимизация

При полностью одинаковой политике переиспользуются подготовленные правила. Пользовательское защищённое хранилище и служба пропускают повторные записи неизменного состояния. Новый элемент очереди по-прежнему подтверждается после надёжного сохранения, а повтор уже сохранённого события не требует ещё одной записи. Полное содержание политик проверяется; сверки только ID/версии для кэша нет.

В файловом сканере уменьшена материализация объектов совпадений, сохранены пределы, тайм-ауты и отмена. На Windows понижается приоритет именно синхронного потока файловой проверки с восстановлением до возврата в пул. Это приоритет, а не жёсткий процент CPU. Для Agent/Session явно зафиксирован Workstation GC (он и ранее был выбором SDK по умолчанию).

Периоды heartbeat/политики/локального обмена не увеличены. DPAPI/ACL/TLS, формат данных и ограничения очередей сохраняются. Дизайн 0.9.0 и помощь/F1 доступны как прежде. Поле подключения уточнено до «Название в консоли».

## Замер на своём Windows-ПК

В launcher добавлена кнопка **«Замерить ресурсы агента — 60 секунд»**. Она открывает отдельное окно, показывает доступные CPU/память Agent и Session и сохраняет локальные CSV/JSON. Сам сборщик, сервер, PostgreSQL и консоль не включаются в эти показатели. Недоступные процессы/счётчики не выдаются за нулевой расход. Сумма рабочих наборов может повторно учитывать общие страницы.

Встроенная помощь объясняет процедуру. Для расширенного замера доступен tools/Measure-Resources.ps1. Тексты буфера/файлов, имена пользователей/ПК, токены и командные строки в отчёт не попадают; автоматической отправки нет. Подробности и ограничения — PERFORMANCE.md в архивах.

## Обновить именно установленный агент

1. В прежнем окне запуска остановить свой сервер, закрыть консоль и launcher.
2. Полный комплект распаковать в новую папку либо маленькое обновление прямо рядом с ЗАПУСТИТЬ.cmd прежнего комплекта с заменой файлов. Во втором архиве внешней папки нет.
3. Запустить новый ЗАПУСТИТЬ.cmd обычным пользователем, запустить сервер, затем нажать **«Агент на этом ПК: установить или обновить»**. В этом выпуске меняются Agent и Session: заменить только файлы комплекта недостаточно для службы.
4. Открыть компонент буфера, дождаться версии агента **0.9.1** в консоли и нужного состояния политики. Затем выполнять замер.

Регистрация/очереди сохраняются. Повторная первичная подготовка и новая миграция базы не требуются. Старое исправление установки включено. Нужны Windows 10/11 x64 и PostgreSQL 17 на сервере; .NET включён в полный комплект. Успех исправления прежней ошибки на ПК пользователя не объявляется подтверждённым.

## Проверено и что ещё предстоит

214 проверок логики/файлов/настоящего PostgreSQL и 24 выполнения live-HTTPS, всего **238 без ошибок/пропусков**. Дополнительно 14 проверок запуска, 12 восстановления установки, 10 сборщика ресурсов; синтаксис 28 PowerShell-файлов. Полный CLI сборщика запускался над реальным процессом PowerShell в Linux с явной отметкой платформы. Проверены self-contained PE Windows x64, режим GC, состав/хеши/целостность ZIP и исключение реальных тестовых секретов. Изменения — changes.diff, хеши — SHA256SUMS.txt.

**Нативные WinForms/WPF, SCM/DPAPI/ACL, Windows PowerShell 5.1, приоритет потока и потребление настоящего Windows-агента здесь не проверены.** Минимальная RAM/CPU и экономия в процентах пока не измерены; переносимые проверки не являются гарантией работы на любом ПК. На рабочем компьютере можно оставить только Agent/Session, вынеся сервер/БД/консоль на другой ПК. Копирование/вставка разрешены; USB/печать/сетевые передачи пока не блокируются. master и прежний OpenDLP сохранены.
