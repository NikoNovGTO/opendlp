Выпуск от 26.11.2026. Исправлены обработка сообщений и подтверждений доставки, добавлена защита браузерных запросов к API. Ключевые слова, ИНН/СНИЛС и несколько правил из 0.10.0 сохранены. Режим — наблюдение: копирование разрешено.

## Что исправлено

- Некорректный ответ локального канала больше не завершает цикл связи Session: сохраняются последняя политика и неподтверждённые события, обмен повторяется.
- Повторяющиеся, чужие и одновременно принятые/отклонённые ID отвергаются до изменения очереди. Проверяются размеры и состав подтверждений. Ошибки записи остаются отдельными от ошибок протокола.
- При чтении канала сначала получается короткий заголовок, затем проверяется клиент, после этого читается и разбирается содержимое. Этот порядок учитывает ImpersonateNamedPipeClient.
- Изменяющие запросы API с чужими браузерными Origin/Fetch Metadata отклоняются. Ответам API задан Cache-Control: no-store. Cookie/Bearer-авторизация сохранена, штатные нативные клиенты совместимы.

[Технический отчёт](SECURITY-REVIEW.md) содержит границы доверия, воспроизведение на прежних сборках, исправления, использованные источники и оставшиеся Windows-испытания. Он также включён в оба основных ZIP.

## Обновление с 0.10.0

1. В старом окне запуска остановить свой сервер, закрыть консоль и окно запуска.
2. Распаковать обновление поверх прежнего комплекта либо полную программу в новую папку.
3. Открыть ЗАПУСТИТЬ.cmd обычным пользователем, проверить готовность и запустить сервер/консоль.
4. Нажать **«Агент на этом ПК: установить или обновить»**, затем заново открыть пользовательский компонент буфера. Для исправлений должны быть обновлены установленные Agent и Session до **0.10.1**.
5. Проверить версию агента, подтверждение политики и реальное новое копирование на ПК агента.

После 0.10.0 новых миграций БД и схем очередей нет: повторная подготовка базы не нужна. Учётные записи, политики, регистрация и очереди сохраняются. При переходе с 0.8/0.9 сначала применить миграцию 0.10 через «Первичная подготовка»; рабочую базу предварительно сохранить резервной копией.

Обновление проверено поверх шести прежних комплектов: исходного и исправленного 0.8.2, 0.8.3, 0.9.0, 0.9.1 и 0.10.0. Все файлы текущей полной поставки совпадают по SHA256.

Это первый целевой проход технической проверки. Среда — Linux. Настоящие Win32 impersonation/ACL, SCM/UAC/DPAPI, WPF/WinForms и захват буфера требуют проверки на Windows. Подключения локального канала обрабатываются последовательно; тайм-аут одного подключения не является полной защитой от локальной перегрузки. Проверку нагрузки и работу под несколькими пользователями нужно выполнить на Windows. Защита от остановки/удаления пользователем и подписанный механизм обновления не реализованы.

Исходный OpenDLP и master сохранены. Контрольные суммы: [SHA256SUMS.txt](https://raw.githubusercontent.com/NikoNovGTO/opendlp/ourdlp-delivery-20261123/deliveries/ourdlp-security-20261126/SHA256SUMS.txt). Подробности внутри ZIP: README.md, SECURITY-REVIEW.md и VALIDATION.md.
